# M5.10 MVP 修正版发布收口

- 状态：completed
- 执行日期：2026-08-29
- 发布版本：`personalmemory-v0.1.2`

## 原因

`personalmemory-v0.1.1` 已固定在早期候选提交，不能移动；其后完成了模型授权与提炼闭环、L1 失败游标保护、本地令牌交互修复和默认端口迁移。为确保安装入口、源码包和实际已验证代码一致，使用补丁版本 `0.1.2` 收口，不覆盖旧 tag。

## 实现

- 默认端口固定为上游核心 `17173`、PersonalMemory Gateway `17175`、Web `17177`，正式安装、远程引导、开发入口、Web 代理和文档统一。
- 全部进程停止后允许显式迁移端口；未显式指定的端口继续沿用可信回执。
- 迁移失败时保留旧回执和已有数据、凭据；部分停止或运行中的端口变更继续 fail closed。
- 产品安装、升级、源码包和远程引导默认版本升级为 `0.1.2`，`personalmemory-v0.1.1` 保持不可移动。

## 验证

- 本机实际安装已迁移到 `17173`、`17175`、`17177`，三个健康入口通过，旧端口释放，Codex/Claude Code Hook worker 健康。
- 最小 L1 已完成 `pending → approved`，受认证 Hook 精确召回返回 `recalled`、1 条且生成不可信上下文；Hook 召回路径只请求 L1。
- 安装器回归覆盖默认端口、自定义端口沿用、运行中拒绝、全停迁移、端口预检失败和 Hook 回执清理失败时旧回执逐字节保留。
- `npm run verify` 全部通过；Standards 与 Spec 双轴独立复审最终均无 P0/P1。
- `npm run release:check` 与版本化源码包生成、摘要校验在本步骤提交前重新执行。

## 发布边界

本步骤只准备本地 annotated tag 和可校验源码包，不移动 `main`、不 push、不创建远端 Release。macOS arm64 与 Linux arm64 的既有真实分发物验收继续有效；本次平台无关修复由全仓自动化、macOS 实机迁移和源码包复验覆盖。
