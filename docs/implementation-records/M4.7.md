# M4.7 收口来源、便携性与普通用户入口承诺

状态：completed

## 三项决定

1. L2/L3 不为满足旧文档承诺而大面积修改上游内核。MVP 保留 L0 和新 L1 的真实来源引用；旧 L1 与 L2/L3 在无可验证引用时统一显示“来源未记录”。完整 L3→L2→L1→L0 链后置。
2. ADR-0003 的可读导出重建保留为长期方向，不进入本次 MVP。JSON/Markdown 导出用于长期阅读、校验和避免锁定，但不能导入、启动新安装或重建索引；跨安装迁移和灾难恢复只承诺已验证完整备份。
3. Web 是日常管理入口，覆盖浏览、审核、纠错、治理、审计、强确认删除和自动 Hook 独立授权；受管 CLI 是系统入口，覆盖安装、状态/Agent 信任、升级、导出、备份恢复、重启、停止和卸载。普通用户无需直接操作 SQLite 或拼原始 API。

正式边界见 [MVP 来源、便携性与普通用户入口边界](../architecture/MVP_USER_BOUNDARIES.md)。该决定替代 PROJECT_RULES 旧第 7 条、ADR-0004 和 DEVELOPMENT_PLAN 中“L2/L3 完整来源追溯”“100% 派生记忆定位原始来源”及“MVP 可读导入重建”的宽泛表述；替代原因是当前上游格式不保存可验证 L2/L3 下级引用，而可读导出也不包含全部运行时事实和索引。

## 落实

- 项目规则、ADR-0003/0004、开发/实施计划、MVP 路线图、当前架构、浏览与可移植数据契约、README 已统一为同一边界。
- Web 设置页移除 Agent/MCP “即将可用”陈旧文案，展示受管 Hook 与 lifecycle 状态入口。
- Web 通过既有版本化 Gateway 契约提供自动召回和自动本地捕获的独立授权/关闭入口；授权前逐项展示服务端版本化披露，授权仍需浏览器安全会话、CSRF、披露版本和 expected revision。披露缺字段或类型错误时 fail closed，不显示授权按钮。
- 设置页明确 Web/CLI 职责、可读导出不可导入及完整备份迁移边界。
