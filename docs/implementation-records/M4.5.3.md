# M4.5.3 实现双客户端事件解析、turn 暂存与 HMAC

- 状态：completed
- 日期：2026-08-18
- 基线：`cf6923c`

## 边界

- 实现 Codex/Claude Code `UserPromptSubmit` 与 `Stop` 解析、主 Agent 过滤、原始 prompt/最终 assistant 配对。
- 私有 turn 暂存固定为 0700 目录、0600 原子文件和无符号链接路径，最多 128 条、逻辑 TTL 1 小时、文件上限 4 MiB；带 owner 存活校验和恢复互斥的跨进程锁避免并发更新丢失并回收崩溃遗留锁。
- Stop 通过随机 token 和 30 秒租约 claim；Gateway 成功或持久 outbox 接纳后才 acknowledge 删除，失败可 release，崩溃后可重领且陈旧 token 不得影响新认领。
- Codex 使用原生 `turn_id`；Claude Code 优先使用 `prompt_id`，旧版本生成不含正文的 HMAC turn 标识。
- 完全相同的前置事件重试复用当前记录；同一原生 turn 的不同正文/cwd 冲突且保留首条；旧版 Claude 当前回合确认删除后为同 session 下一回合生成新标识。
- 捕获幂等键只对契约版本、client、installation、session、turn 做安装级 HMAC-SHA-256，不包含 prompt、assistant 或 cwd。
- 不安装 Hook、不修改用户配置、不请求 Gateway、不实现 outbox 或生产捕获。
- 本步骤的短命 Hook 进程会在每次访问时物理清除过期正文；没有后续事件时的定时磁盘清扫依赖 M4.5.4 接入常驻本地服务，不在本步骤虚构常驻保证。

- [x] 独立审查无 P0/P1；P2 已修复或明确接受。

已接受 P2：短命 Hook 进程的崩溃锁以 PID 存活状态判断 owner；同一次开机中若 PID 在下一次访问前恰好被复用，旧锁会继续 fail-open 拒绝自动捕获，直至该无关进程退出或用户清理锁。目标 macOS/Linux 没有可由受限 Node Hook 统一使用、且无需外部子进程的进程启动实例 API；外部 `ps` 已在受管客户端中验证会被拒绝，保留它反而造成确定性门禁失败。该风险不读取、覆盖或外传正文，概率低且可诊断；M4.5.4 接入常驻本地服务后改由常驻进程持有 OS 级互斥并消除此限制。
