# M4.5.2 实现 Gateway Hook Adapter 与本地持久化边界

- 状态：completed
- 日期：2026-08-18
- 基线：`ac9a340`
- 数据库版本：8

## 实施前检查

- 目标：实现认证的 Hook recall/capture 路由、服务端授权与策略 revision 校验、approved L1 有界召回，以及不保存正文的持久化捕获幂等账本。
- 非目标：不安装 Codex/Claude Code Hook，不实现客户端事件解析、turn 暂存、HMAC 生成、outbox、敏感内容规则、模型外联配置或真实客户端 E2E。
- 安全边界：现有上游 `/capture` 可能触发模型处理；M4.6 的权威模型外联门禁完成前，自动 Hook 不得直接调用该路径。捕获只进入显式注入的本地 `HookCaptureSink`，生产默认关闭。
- 验收：路由使用 Bearer/session 认证并严格解析 M4.5.1 契约；服务端状态覆盖客户端声明；召回仅含 approved L1；重复与冲突可跨重启识别；幂等表不保存正文、cwd 或客户端配置。

## 实现

- 新增 schema v8 `personalmemory_hook_captures`，仅保存幂等 HMAC、独立 payload SHA-256、状态与时间戳。
- 新增 `HookCaptureLedger`，在同一 SQLite `BEGIN IMMEDIATE` 事务内执行同步本地写入与幂等落账；sink 必须使用传入的活动数据库事务并同步返回唯一提交凭证，Promise 或错误凭证会整体回滚。成功后重试返回 duplicate，相同键不同载荷返回 conflict。
- 新增 `HookLifecycleService`，集中执行安装、授权、策略 revision、来源策略、approved L1 与预算门禁。
- 新增 `POST /api/v1/hooks/recall` 和 `POST /api/v1/hooks/capture`；两者复用 Gateway 认证、限流、请求体上限、安全响应头和脱敏路由日志。
- Hook 专用脱敏遥测记录客户端、操作、结果、耗时、召回预算使用量和不可逆幂等引用；conflict 与本地 sink 故障按错误告警，禁止记录正文、cwd、session/turn 原值。
- Gateway 生产接线默认关闭两项授权且不注入 capture sink，避免在 M4.6 前绕过零外联承诺。
