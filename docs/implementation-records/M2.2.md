# M2.2 会话捕获与导入

- 状态：completed
- 日期：2026-08-10
- 基线：`69f733e`

## 交付范围

- 增加单会话捕获、批量导入、进度、失败重试和取消 API。
- 数据库 schema 升级到 v2，持久化任务、轮次、幂等哈希、尝试次数和安全错误码。
- 按轮次执行上游 `/capture`，部分失败重试不重复发送已成功轮次。
- 支持 assistant/user 与 user/assistant 两种成对顺序，拒绝非法角色和不完整轮次。
- 保持 loopback 直连、默认零外联；模型启用时先披露 provider、origin 和发送字段并要求显式确认。
- 结构化日志和 API 错误不记录会话正文、模型密钥或上游私密响应。

## 非目标

- 本步骤不实现召回、列表、修改、导出或彻底删除。
- 本步骤不承诺导入完成即已完成 L1 提炼；上游调度状态继续由上游响应管理。
- 不并发发送多个轮次，先保证本地资源可控和确定性失败恢复。

## 审查结论

首轮复审发现 2 项 P1：completed 任务可被错误置回 pending；停机时数据库可能先于导入执行器关闭。
修复为只允许 failed/partial/cancelled 重试，并在关闭数据库前取消、等待全部执行器。

第二轮复审发现 1 项 P1：进程在任务入账但未开始时退出会留下不可重试 pending。
修复为启动时将遗留 pending/running 恢复为 `INTERRUPTED`，保留 completed 轮次；已请求取消的任务恢复为 cancelled。
同时补充 v1→v2 数据保留测试，并把模型披露字段明确到 imported conversation messages。

最终结论：P0=0、P1=0、P2=0。M2.2 完成，可以进入 M2.3。
