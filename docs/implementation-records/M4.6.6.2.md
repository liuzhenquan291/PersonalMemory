# M4.6.6.2 实现保留期执行与恢复防复活门禁

状态：completed

## 范围

- 版本化保留期执行授权精确绑定披露版本、策略 revision、L0/L1 天数和受管副本整件删除方式；授权默认关闭，绑定变化、撤销或账本异常均停止物理清理。
- 持久运行账本、短租约和受管维护 worker 以冻结截止点执行有界批次；L1 复用 M3.4 级联顺序但保留尚未越过独立 L0 截止点的来源，L0 在可读资产和登记副本处理成功后再清理上游元数据与索引。
- 备份与清理、恢复、升级和彻底删除共享生命周期互斥；有效授权下备份必须在同一冻结策略下确认 `drained`。
- 恢复前从当前安装生成带摘要的私有授权/策略封套和单次受管副本快照。旧备份仅在 staging 中迁移、应用当前封套、合并恢复前活动副本并排空；切换后先删除已登记的恢复输入备份，再允许服务启动。
- staging 强制使用 loopback、本地状态、本地 SQLite，并禁用模型、embedding 和全部远端遥测。封套摘要不含路径，单次含路径快照使用 `0600` 权限且在成功或失败后删除。
- staging、切换后输入备份处理或最终化任一步骤失败时，恢复原数据；doctor/worker 状态只保留脱敏、定界统计。

## 明确非目标

- 不清理 L2/L3，不改变显式彻底删除的全来源语义，也不把保留天数本身视为删除授权。
- 不把未登记、已移动或已改名的导出/备份宣称为可追踪副本。
- 不扩展团队、远程控制面或普通用户 Web/CLI 信息架构；这些仍按现有 MVP 边界后置。
