# M5.2 升级和数据库迁移

- 状态：completed
- 完成日期：2026-08-12
- 提交：本记录随功能提交；提交 SHA 在提交后任务报告中记录
- 实施范围：新增 `npm run upgrade:product`，提供产品/schema 版本检测、磁盘空间门槛、目标构建、受管进程停止、升级前备份与校验、显式 migration runner、重启与健康检查、成功回执更新和失败自动恢复。
- 前置修复：M5.1 的回执、日志和凭据从记忆数据根迁移到独立私有状态目录，避免违反 M2.6 的备份资产边界。
- 安全边界：只接受严格匹配状态目录和数据根的受管回执；拒绝符号链接资产和扩张路径；要求可用空间至少为数据大小两倍加 128 MiB；不联网下载或执行远程脚本；升级备份成功后不自动删除。
- 自动验证：`npm run test:upgrade` 覆盖前版升级、当前版本重复执行、空间不足前置拒绝、迁移中断恢复、恢复失败 fail closed 和恶意回执路径拒绝；既有 migration runner 测试覆盖事务回滚、重复迁移、旧 schema fixture、校验和和版本间隙。
- 验证证据：`npm run verify` 全部通过，包括格式、lint、边界、构建、类型、上游与产品测试、安装/升级/数据测试、黄金链路和 TypeScript SDK 测试。
- 审查结论：按回执、路径、空间、停止、备份、迁移、启动和回滚顺序复查；修复升级失败后恢复含过期 PID 旧回执的 P1，改为数据恢复后保持服务停止并给出恢复入口。修复后无未解决 P0/P1/P2。
- 下一步依赖：M5.3 提供用户可操作的停止、状态修复、备份、恢复和安全卸载命令。
