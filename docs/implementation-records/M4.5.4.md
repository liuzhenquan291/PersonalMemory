# M4.5.4 实现 Hook Runtime 与私有有界 outbox

- 状态：completed
- 日期：2026-08-19
- 基线：`b44cffa`

## 边界

- 只通过带 Bearer 的显式 loopback HTTP Gateway 调用 `/api/v1/hooks/recall` 与 `/api/v1/hooks/capture`，禁止重定向；UserPromptSubmit 从 turn 暂存开始共享 1 秒绝对 deadline，取消信号贯穿 turn-store 锁等待/读写和 Gateway 请求，避免截止后继续落盘，Gateway 只获得剩余预算；捕获 HTTP 调用限制为 1 秒，响应正文分别限制为 16 KiB 与 4 KiB。
- 严格校验 Gateway 公共响应，并把召回正文只编码到 Codex/Claude Code 的 `hookSpecificOutput.additionalContext`；无召回、无效事件或任意运行错误均返回允许客户端继续的空对象。
- 仅网络错误、超时或 HTTP 502/503/504 可排队；鉴权、契约、策略、重复和冲突结果按终态处理，不进行无界重试。
- 私有 outbox 固定为 0700 无符号链接目录、64 个 0600 原子槽位、单项 256 KiB、正文 TTL 24 小时和 30 秒 claim 租约；并发同键去重、异载荷冲突，同一项仅允许一个消费者 flush。
- 单项最多尝试 5 次，退避为 1 秒、5 秒、30 秒、60 秒；耗尽后保留 failed 状态至 TTL。状态接口只暴露 queued、failed、total，不返回正文、cwd、密钥或 payload。
- Stop 只有在 Gateway 返回终态、不可重试协议终态或 outbox 已持久接纳后才 acknowledge 并删除 turn；outbox 写入失败会 release，供后续安全重领，非重试错误不会由重复 Stop 无界重发。
- 前台 Hook 不同步 flush backlog，避免维护工作突破召回 1 秒预算；独立维护接口执行到期清理和可投递项 flush，留给后续受管 worker 调度。本步骤只提供 Runtime、flush 与状态接口，不安装客户端 Hook、不启动常驻 worker、不接 Web/doctor，也不接生产捕获 sink。
- M4.6 完成统一模型外联门禁前，生产捕获仍保持默认关闭；本步骤不以自动本地捕获授权代替模型外联授权。
