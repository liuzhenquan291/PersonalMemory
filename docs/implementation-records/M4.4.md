# M4.4 第二客户端可移植性验证

- 状态：completed
- 日期：2026-08-12
- 基线：`b32d6d1`
- 第二客户端：Claude Code `2.1.228`

## 交付范围

- 选择 Claude Code 作为第二个非 Codex 客户端，保留 MCP 1.0 五工具契约、Gateway API 和 Server 实现不变。
- 将 Codex 的五工具 Gateway fixture 抽为客户端无关模块，两端使用相同搜索词、页大小、召回正文、来源、预算、捕获消息、幂等键、审核版本和遗忘 handoff 断言。
- Claude Code 只加载临时 MCP JSON，严格忽略其他 MCP 配置，关闭会话持久化和内置工具，只白名单 `mcp__personalmemory__*` 五个工具；HOME、settings 和配置目录全部隔离。
- 使用 loopback 确定性 Anthropic Messages API fixture 逐轮发出标准 `tool_use`，真实 Claude Code 负责发现 MCP 工具、传参、执行并把结果回送；fixture 不直接调用 MCP，也不替代客户端。

## 自动化与真实验收

- `npm run test:mcp-client-config` 覆盖闭合输出 schema、安全提示、五工具白名单和 loopback stdio 配置，并保留 Codex 安装保护的 9 个回归场景。
- `npm run test:codex-e2e` 在共享 fixture 抽取后重新通过，证明既有客户端基线未漂移。
- `PERSONALMEMORY_CLAUDE_BIN=/absolute/path/to/claude npm run test:claude-e2e` 使用真实 Claude Code `2.1.228` 完成搜索、读取、捕获、反馈和遗忘交接五次工具调用。
- 每轮模型 fixture 校验 Claude Code 只宣告同一五工具、上一轮 `tool_result` 成功且包含预期结构；Gateway fixture 再校验实际 HTTP 请求，因此不是仅检查最终文本。
- 提示注入正文只作为搜索/读取结果回传，终局 `prompt_injection_followed=false`；遗忘结果包含 `destructive_action_performed=false`，终局 `deletion_claimed=false`。

## 行为差异与审查结论

- Codex 可按工具配置审批模式；Claude Code 验收通过进程级工具白名单和 `dontAsk` 运行，产品默认仍要求写工具提示确认，M5 不得把测试专用自动批准写入用户配置。
- Claude Code 把 MCP 文本结果包装为 JSON 字符串，成功 `tool_result` 可省略 `is_error=false`，并为 `--json-schema` 注入内部 `StructuredOutput` 工具及可能额外一次终局收口；fixture 要求 PersonalMemory MCP 工具精确为五个、唯一额外工具为该内部输出工具，未修改 Server 或 Gateway。
- 首轮外部推理网关返回 503，证明公网模型不适合确定性退出门；最终验收锁定 loopback mock LLM，符合 E2E-02 的默认无外网与确定性要求。
- 未发现 P0/P1；跨客户端差异局限在配置、工具命名和结果包装，核心契约无客户端分支。
