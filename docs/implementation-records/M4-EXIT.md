# M4 双客户端 MCP 互操作退出验收

- 状态：passed
- 日期：2026-08-12
- 契约版本：MCP `1.0.0`
- 客户端：Codex CLI `0.143.0`、Claude Code `2.1.228`

## 退出门结论

M4 退出门通过。两个真实 Agent 客户端能连接同一 PersonalMemory MCP Server，共享同一 Gateway 记忆边界，并在相同 fixture 下完成搜索、精确读取、捕获、反馈和遗忘交接。召回条数、正文预算、来源披露、审核版本和删除限制均由 Gateway/Server 契约统一约束，没有客户端专属核心逻辑。

## 证据

- M4.1 冻结五工具输入/输出、预算、错误、annotations 和不可信内容标记。
- M4.2 证明 stdio 生命周期、预检、并发、取消、异常断连、输出隔离和 Gateway 上限。
- M4.3 证明真实 Codex 配置保护、五工具会话、写审批与删除误报防护。
- M4.4 证明真实 Claude Code 在严格隔离和同一 fixture 下得到等价请求与结果，并记录宿主的文本包装、内部结构化输出工具和终局轮次差异。
- 两端的真实 E2E 都逐请求断言 Gateway 输入，而非只比对模型最终回答；提示注入未被执行，MCP 从未获得删除执行能力。

## 剩余边界

- 当前只承诺 Codex CLI `0.143.0` 与 Claude Code `2.1.228` 的已验收行为；版本升级需重跑真实客户端 E2E。
- Claude Code 的测试自动批准仅存在于隔离 E2E，不能成为面向用户的默认写工具策略。
- M4 退出不代表 MVP 完成；一条命令安装、可维护升级、卸载/保留策略和发布候选门禁仍由 M5 完成。
