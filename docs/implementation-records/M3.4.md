## 审查修正

- 删除凭据的正文摘要加入计划专用随机盐，避免低熵记忆正文形成可离线枚举的稳定 SHA-256 指纹。
- L1 索引安排在来源、派生、可读副本、登记副本和产品治理元数据之后删除；若进程在末步前中断，上游 L1 仍可按已知 ID 重新预览，若末步已完成则此前受控资产已清理。
- JSONL 逐行 fail-closed 解析并在同目录原子替换；任何符号链接、非法登记格式或数据根内路径都会让对应步骤失败，而不是扩大删除范围。
- 任一前置清理失败时跳过最终 L1 索引删除，使进程重启后仍能按已知 ID 重新预览；临时 JSONL 文件在失败路径也会显式清理。
- 审计继续保留 HMAC 引用证明，不把 raw ID、正文、理由或来源内容复制进事件；部分删除按失败结果落账。
- 视觉复核移除彻底删除流程中的普通来源/治理卡片，只保留直接影响不可逆决定的范围、限制、确认和残留凭据。

## 已知边界

- 只自动处理真实 `source_message_ids` 和正文完整精确匹配；缺少来源、语义改写后的 L2/L3 内容和用户自行复制、移动或同步的文件不能自动归因。
- 待执行预览保存在进程内并在十分钟后过期；部分失败计划最多保留一小时用于重试，避免正文副本在长运行进程中无限驻留。进程中断会保留 tombstone；L1 末步尚未执行时可用已知 ID 重新调用预览，Web 暂无全局“未完成删除任务”列表。
- 审计事件和 tombstone 为防复活及责任证明而保留，但不含正文或操作理由；更长期的回退目录、日志和卸载生命周期仍由 M5.3/M5.4 收口。
