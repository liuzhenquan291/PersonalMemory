## 真实分发物发现并修复

1. 发布秘密扫描会把测试中的完整私钥头当作候选泄漏；测试向量改为运行时拼接，敏感识别断言保持有效。
2. 干净包在 `npm ci` 后直接导入尚未构建的 workspace `dist`；安装入口现先执行产品构建，发布扫描固定检查该步骤。
3. 上游 Gateway 会在产品 Gateway 安全检查前以非私有权限创建数据目录；安装器现先复用 core 的 `initializeDataDirectory` 完成符号链接、祖先所有权和 `0700` 校验，再启动任何服务。
4. 产品 Gateway 未收到 M4.6.6 后要求的 `PERSONALMEMORY_STATE_DIR`；安装器现显式传递受管状态目录。
5. worker 与 Gateway 同时启动时会在 Gateway 就绪前首次同步失败，30 秒安装窗口内无法恢复；worker 现只在三个健康入口与非降级召回通过后启动。
6. 根项目安全锁文件已更新，但 TypeScript SDK 独立锁文件仍保留易受影响的 `nanoid 3.3.17`；最终官方审计发现后将 SDK 锁定解析最小升级至 `3.3.18`，SDK 35 项测试与官方审计通过。
7. 最终全量门禁在并发压力下复现 outbox 相同幂等键入队竞态：一个调用枚举到另一调用即将删除的 `.tmp` 后，后续 `lstat` 返回 `ENOENT`。临时文件清理现把该结果视为已清理，其他文件系统错误继续抛出；原回归连续 100 轮和后续完整门禁通过。
