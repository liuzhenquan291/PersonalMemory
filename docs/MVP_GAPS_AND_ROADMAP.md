# PersonalMemory MVP 缺口与后续路线

> 状态：生效
>
> 日期：2026-08-13
>
> 用途：记录 M0–M5 基线完成后的产品复盘、MVP 重新开放原因、后续实现顺序和最终产品差异，作为新会话接手入口。

## 1. 当前结论

M0–M5 已完成的核心闭环、治理、MCP、安装、升级、备份恢复和发布工程仍然有效，但当前产品只能证明 Agent **可以调用** PersonalMemory 的 MCP 工具，不能证明用户在自然使用 Agent 时会自动召回和维护记忆。

用户已确认：**自动记忆生命周期是 MVP 的核心体验，而不是可选增强。** 因此撤回“完整 MVP / 本地发布候选”结论，重新开放 MVP。完成本文件第 4 节的阻断项、重新执行受影响的 M5 验证之前，不移动 `main`、不推送、不对外发布。

当前准确状态是：

- Chat Memory 核心与手动 MCP 闭环已完成；
- Codex/Claude Code 的 MCP 协议可移植性已验证；
- 一条命令服务安装、生命周期和数据治理基线已完成；
- 自动 Hook、普通用户 Agent 安装体验及若干产品承诺仍待补齐；
- 当前电脑尚未安装 PersonalMemory Hook；现有 token usage `Stop` Hook 与 PersonalMemory 无关。

## 2. 已确认的自动记忆生命周期

### 2.1 自动召回

- 在用户提示提交、模型开始处理前触发；Codex/Claude Code 首版采用各自的 `UserPromptSubmit` 等价生命周期事件。
- 使用未被记忆注入污染的原始用户提示查询 PersonalMemory Gateway。
- 自动注入只允许包含 `approved`、未失效、未删除、未被冲突/替代门禁抑制的记忆；不得绕过 PersonalMemory 的治理层直接读取上游存储。
- MVP 默认不自动注入原始 L0 对话或 `pending`/`rejected` L1。
- 注入内容必须标记为不可信记忆，受统一条数、字符、估算 token 和超时预算约束；初始目标为最多 5 条、约 4,000 字符/1,000 token、约 1 秒。
- 召回失败时 fail-open：不注入记忆但继续正常对话，不用记忆故障阻断 Agent。

### 2.2 自动捕获

- 在主 Agent 成功完成一轮回答后触发；Codex/Claude Code 首版采用各自的 `Stop` 等价事件。
- 仅保存本轮成对的原始 user/assistant 文本，不保存 system/developer 指令、工具调用/输出、附件、base64 或已注入的记忆块。
- 失败、中断、空回复和子 Agent 轮次默认不捕获。
- 幂等键必须稳定绑定 Agent、session 和 turn；重复 Hook 不重复写入，相同键不同载荷必须冲突并告警。
- Gateway 可达时使用现有持久化捕获任务；不可达时进入容量、条数和 TTL 有界的私有本地 outbox，后台有限重试并在 Web/doctor 显示积压，不能静默丢失。
- 自动捕获本身是本地写入，不调用模型；L1–L3 提炼是否调用模型由独立模型策略决定。

### 2.3 人工控制边界

- 首次安装分别授权“自动召回”和“自动本地捕获”；授权后不再每轮确认。
- 全局及按 Agent、项目/工作目录、来源提供暂停和排除能力。
- Agent 主动调用手动捕获工具时仍逐次确认，避免把任意工具调用等同于已授权的生命周期捕获。
- 新提炼的 L1 仍默认进入 `pending`，只有人工批准后才能自动召回。
- 反馈、纠错、合并、冲突/替代关系和遗忘交接仍需用户明确操作；彻底删除仍回到 Web 重新核对范围并强确认。
- 本地捕获授权与模型外联授权分离。模型 provider、origin 或发送字段变化时必须重新同意；未同意时允许保留 L0，但暂停需要该模型的提炼。

## 3. 当前实现与目标的差异

### 3.1 Agent 接入不是自动 Hook

- `scripts/personalmemory-codex.mjs` 当前只安装五个 MCP 工具，搜索/读取自动批准，捕获/反馈/遗忘交接逐次提示；没有安装 Hook。
- Claude Code 当前只有隔离 E2E 配置，没有面向用户的安装、卸载和 Hook 管理入口。
- 现有真实客户端 E2E 通过提示词明确要求调用五个工具，不能证明自然会话会自动召回或捕获。
- Web 设置页仍显示 MCP “即将可用”，与实际协议状态和产品目标不一致。
- OpenClaw 的 `before_prompt_build`/`agent_end` 可借鉴生命周期、原提示缓存和清洗方式，但其召回路径不能原样复用；新适配器必须经过 PersonalMemory Gateway 的审核、治理和预算门禁。

### 3.2 自动采集的隐私控制不足

- 计划承诺的敏感信息识别、来源级采集开关和用户可配置保留期尚未产品化。
- 当前 L0 清洗主要移除框架注入、媒体噪声和记忆回灌标签；L0 仍是宽松原文档案，不等同于密码、API key 或个人敏感信息识别。
- 上游 `excludeAgents` 主要影响调度，尚不能作为产品层“写入 L0 前”的权威策略门禁。
- 自动 Hook 上线前必须在服务端实现全局、Agent、项目/来源策略，并在 L0 落盘前执行。

### 3.3 模型配置、外联授权与提炼链割裂

- 产品 Gateway 的 `PERSONALMEMORY_MODEL_ENABLED` 默认关闭，并具有 HTTPS、origin allowlist 和密钥约束；这是需要保留的安全基础。
- 安装器当前固定产品模型关闭，但启动上游核心时没有把该开关统一映射为权威出站门禁；上游另有 `TDAI_LLM_*` 配置。必须先统一配置和网络控制，再宣称默认零外联及自动提炼可靠。
- Web 当前只显示模型“已配置/关闭”，没有普通用户可用的 provider、地址、发送字段、授权、连通性验证和停用流程。
- 现有捕获 API 在模型启用时要求逐请求确认，而 Hook/MCP 不能替用户授予外联同意。应改为在 Web/安装流程保存版本化授权，Hook 仅引用授权及策略版本。

### 3.4 来源追溯承诺尚未完全达到

- 新 L1 可以记录真实 L0 来源消息 ID。
- L2/L3 当前没有可验证的下级引用，只能诚实显示“来源未记录”。
- 这与“L2/L3 首版提供来源追溯”和“100% 派生记忆可定位原始来源”的文档承诺冲突。
- MVP 必须二选一：补齐 `L3 → L2 → L1 → L0` 链，或正式收窄 MVP 的来源追溯承诺；不得继续同时保留相互冲突的声明。

### 3.5 便携与普通用户入口仍不完整

- 完整备份可以恢复到另一安装，可读 JSON/Markdown 可以导出。
- 尚没有从可读导出重新导入并重建索引的产品路径；当前“迁移”实质依赖完整备份。
- Web 尚未覆盖会话导入、导出、备份和恢复等全部日常入口，部分闭环仍依赖 CLI/API。
- 若继续宣称面向普通用户的产品化 MVP，应补入口或明确第一版哪些动作仍由单一 CLI 完成。

### 3.6 支持与发布限制

- Codex 有 MCP 配置安装器；Claude Code 仅完成协议 E2E，没有正式安装器。
- 当前实测发布矩阵是 macOS arm64 和 Linux arm64；x64、Windows 未验证。
- 首版分发是版本化源码包，需要 Node.js/npm；桌面封装、签名安装包和自动更新尚未实现。
- 正式发布前仍需完成名称、域名、商标和发布渠道重名检查。

## 4. 阻断 MVP 完成的后续任务

### M4.5 自动 Agent 记忆生命周期

1. 冻结跨客户端 Hook 输入/输出、授权、预算、幂等、失败和隐私契约。
2. 实现只通过 PersonalMemory Gateway 的公共本地 Hook Adapter。
3. Codex：安装/卸载受管 Hook，保留用户配置，处理 Hook trust，记录可验证回执。
4. Claude Code：提供正式安装/卸载及等价 Hook 配置，不复用测试专用 `dontAsk` 设置。
5. 实现自动召回、成功轮次自动捕获、注入不回写、失败不中断和有界 outbox 重试。
6. 实现全局及按 Agent/项目/来源采集策略、敏感内容排除和用户可见状态。
7. 更新 Web：显示 Agent/Hook 健康、授权状态、最近成功、失败和 backlog；移除“即将可用”陈旧文案。
8. 真实自然对话 E2E：用户不说“保存/搜索”，仍验证前置召回、轮后捕获、重复 Stop、中断、重试、pending 不召回和注入不回写。

### M4.6 模型与隐私配置收口

1. 统一产品 Gateway 与上游核心的模型配置和权威出站门禁。
2. 默认零外联实测，包括存在继承环境变量、代理变量和错误配置的情况。
3. 提供本地/OpenAI-compatible provider 的单一配置入口、发送字段披露、版本化同意、连通性测试和关闭流程。
4. 未授权时允许 L0 本地捕获但暂停 L1–L3 模型提炼；不得让整轮捕获返回失败。
5. 增加敏感信息规则、采集开关和 L0/L1 保留期的普通用户设置与审计。

### M4.7 现有承诺收口

1. 决定并实现或收窄 L2/L3 来源追溯承诺。
2. 决定可读导出重建能力是否列入本次 MVP；若列入，完成导入、schema 校验、索引重建和迁移 E2E。
3. 明确 Web 与 CLI 的普通用户边界，补齐必要入口和首次使用指引。
4. 修正文档、状态页和 README，保证“已验证能力”“已知限制”“后续路线”一致。

### M5.5 重新发布验证

M4.5–M4.7 的适用阻断项完成后，重新执行：

- Codex/Claude Code 安装、信任、重复安装、升级、卸载和配置保护；
- 自动召回/捕获的 macOS/Linux 真实 E2E；
- 默认零外联、模型启用/撤销、敏感采集策略和失败注入；
- Hook outbox、重启恢复、重复事件与长期运行；
- 源码发布包从空机安装到首条自动召回/捕获；
- 完整回归、独立审查及 P0/P1/P2 门禁。

只有 M5.5 通过后，才重新评估“完整 MVP / 发布候选”、移动 `main`、推送和对外发布。

## 5. 有意留到 MVP 之后的产品能力

以下属于最终产品路线，不阻断当前 Chat Memory MVP，除非后续用户重新调整范围：

- Skill Memory：从成功任务和工具轨迹提炼可复用流程；
- Wiki Memory：导入和组织个人文档知识；
- CodeGraph：文件、符号、调用关系和影响范围；
- CodeBuddy 及更多 Agent 适配器；
- 按项目、来源和记忆类型装配 Agent 上下文；
- 增量同步、失败隔离和更完整的召回质量仪表盘；
- L2/L3 的复杂结构化编辑、审核和冲突治理；
- 多设备同步、可选远端部署、高级插件生态和家庭空间；
- 桌面应用、签名二进制、自动更新、Windows 和更多 CPU 架构；
- 跨设备/多用户前需要重新评估的应用级静态加密与密钥管理。

## 6. 明确非目标

- 多组织、多团队和复杂 RBAC；
- 企业计费、SLA 和大规模集群部署；
- 公共技能市场；
- 不可审阅、不可纠错、不可追溯的全自动记忆写入；
- 为加入自动 Hook 而重写上游记忆内核或在核心契约中加入客户端特例。

## 7. Token 与性能预算

- 普通 command Hook 本身不天然消耗模型 token；只有调用模型或向 Agent 上下文注入内容才增加 token。
- 自动本地捕获不得调用模型，因此不增加 Agent 对话 token；后台 L1–L3 提炼单独计量和展示。
- 自动召回会增加输入 token，必须设置相关性阈值和硬预算；初始目标约为每轮最多 1,000 token，后续以实测质量和成本调整。
- Hook 不得再次调用 Agent 形成隐藏对话轮次，也不得因失败触发无界重试。
- 产品应分别展示 Agent 对话、召回注入和后台提炼的开销，避免用户把统计 Hook、捕获 Hook与模型费用混淆。
