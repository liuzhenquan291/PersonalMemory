## 1. 当前结论

M0–M5 已完成的核心闭环、治理、MCP、安装、升级、备份恢复和发布工程仍然有效。2026-08-13 复盘时产品只能证明 Agent **可以调用** MCP 工具；此后 M4.5–M4.7 已补齐受管双客户端 Hook、自动召回/本地捕获、授权与采集策略，并收窄无法证明的来源和便携性承诺。当前不再把复盘时的缺口描述为现状。

用户已确认：**自动记忆生命周期是 MVP 的核心体验，而不是可选增强。** 因此曾撤回“完整 MVP / 本地发布候选”结论并重新开放 MVP；本文件第 4 节阻断项和受影响的 M5.5 重新验证现已完成。移动 `main`、推送和对外发布仍需用户明确授权。

当前准确状态是：

- Chat Memory 核心与手动 MCP 闭环已完成；
- Codex/Claude Code 的 MCP 协议可移植性已验证；
- 一条命令服务安装、生命周期和数据治理基线已完成；
- M4.5 自动 Hook、M4.6 模型/隐私门禁和 M4.7 承诺收口已经完成，受管安装现会配置 Codex/Claude Code Hook；
- M5.5 已通过 macOS arm64 与 Linux arm64 真实分发物重新发布验证；覆盖双客户端自然 Hook/受管定义、首条自动召回与捕获、升级、默认零外联、模型与 Hook 授权变化、敏感采集、故障/outbox 恢复、重复事件、长期运行、备份恢复和卸载，并在验收中修复干净包启动与独立锁文件安全问题。

## 2. 已确认的自动记忆生命周期

### 2.1 自动召回

- 在用户提示提交、模型开始处理前触发；Codex/Claude Code 首版采用各自的 `UserPromptSubmit` 等价生命周期事件。
- 使用未被记忆注入污染的原始用户提示查询 PersonalMemory Gateway。
- 自动注入只允许包含 `approved`、未失效、未删除、未被冲突/替代门禁抑制的记忆；不得绕过 PersonalMemory 的治理层直接读取上游存储。
- MVP 默认不自动注入原始 L0 对话或 `pending`/`rejected` L1。
- 注入内容必须标记为不可信记忆，受统一条数、字符、估算 token 和超时预算约束；初始目标为最多 5 条、约 4,000 字符/1,000 token、约 1 秒。
- 召回失败时 fail-open：不注入记忆但继续正常对话，不用记忆故障阻断 Agent。

### 2.2 自动捕获

- 在主 Agent 成功完成一轮回答后触发；Codex/Claude Code 首版采用各自的 `Stop` 等价事件。
- 仅保存本轮成对的原始 user/assistant 文本，不保存 system/developer 指令、工具调用/输出、附件、base64 或已注入的记忆块。
- 失败、中断、空回复和子 Agent 轮次默认不捕获。
- 幂等键必须稳定绑定 Agent、session 和 turn；重复 Hook 不重复写入，相同键不同载荷必须冲突并告警。
- Gateway 可达时使用现有持久化捕获任务；不可达时进入容量、条数和 TTL 有界的私有本地 outbox，后台有限重试并在 Web/doctor 显示积压，不能静默丢失。
- 自动捕获本身是本地写入，不调用模型；L1–L3 提炼是否调用模型由独立模型策略决定。

### 2.3 人工控制边界

- 首次安装分别授权“自动召回”和“自动本地捕获”；授权后不再每轮确认。
- 全局及按 Agent、项目/工作目录、来源提供暂停和排除能力。
- Agent 主动调用手动捕获工具时仍逐次确认，避免把任意工具调用等同于已授权的生命周期捕获。
- 新提炼的 L1 仍默认进入 `pending`，只有人工批准后才能自动召回。
- 反馈、纠错、合并、冲突/替代关系和遗忘交接仍需用户明确操作；彻底删除仍回到 Web 重新核对范围并强确认。
- 本地捕获授权与模型外联授权分离。模型 provider、origin 或发送字段变化时必须重新同意；未同意时允许保留 L0，但暂停需要该模型的提炼。

## 3. 当前实现与目标的差异

### 3.1 Agent 接入（已由 M4.5 收口）

- 五个 MCP 工具继续承担手动调用；捕获/反馈/遗忘交接逐次提示，与自动 Hook 授权分离。
- 受管安装已覆盖 Codex/Claude Code Hook、定义保护、信任回执、维护 worker 和可逆卸载。
- Web 设置页已移除“即将可用”，提供自动召回与自动本地捕获的独立授权，并指向脱敏 lifecycle 状态命令。
- OpenClaw 的 `before_prompt_build`/`agent_end` 可借鉴生命周期、原提示缓存和清洗方式，但其召回路径不能原样复用；新适配器必须经过 PersonalMemory Gateway 的审核、治理和预算门禁。

### 3.2 自动采集隐私控制（已由 M4.6 收口）

- Gateway 已在 L0 与幂等落账前执行全局暂停、按 Agent、工作目录树和来源排除策略，并对凭据、支付卡号和中国居民身份证号命中整轮阻断。
- L0/L1 保留期已有版本化权威策略和认证 API；自动物理清理由 M4.6.6.2 通过受保护清理器接入并完成恢复防复活验收。
- 客户端清洗仍只是纵深防护；产品 SQLite 中的服务端策略才是权威门禁。

### 3.3 模型配置与外联授权（已由 M4.6 收口）

- 产品模型默认关闭；受管启动会清除继承的模型与代理环境，并把产品开关映射为上游最终出站门禁。
- provider、目标 origin 和发送字段由版本化授权账本绑定，任一项变化都会使旧授权失效；未授权或撤销时保持 L0 本地捕获并阻断模型提炼与外联。
- Web 已提供首版 OpenAI-compatible 模型配置、发送字段披露、授权与撤销入口；API Key 只写入私有受管环境文件且不会回传。Web 不直接重启进程，配置或授权变化后仍由用户执行受管 restart。
- Hook 的 L0 本地事务提交后会在事务外异步通知上游 `StatefulPipelineManager`；上游继续拥有 warmup、累计轮数和空闲刷新触发语义。通知或提炼失败保留 L0，新 L1 仍先进入 pending。

### 3.4 来源追溯承诺（已由 M4.7 收口）

- 新 L1 可以记录真实 L0 来源消息 ID。
- L2/L3 当前没有可验证的下级引用，只能诚实显示“来源未记录”。
- MVP 已正式收窄为：L0 与带真实引用的新 L1 提供可验证来源；旧 L1 和 L2/L3 明确显示“来源未记录”，完整 `L3 → L2 → L1 → L0` 链后置。
- 所有返回项都必须披露来源可用性，不能用相似检索伪造来源关系。

### 3.5 便携与普通用户入口（已由 M4.7 收口）

- 完整备份可以恢复到另一安装，可读 JSON/Markdown 可以导出。
- 可读导入与索引重建明确后置；MVP 跨安装迁移和恢复只承诺已验证完整备份。
- Web 负责日常记忆治理和自动 Hook 授权；受管 CLI 负责安装、状态、Agent 信任、升级、导出、备份恢复、停止和卸载。
- 普通用户不需要直接操作数据库或拼原始 API；首版不宣称所有系统管理动作都有 Web 按钮。

### 3.6 支持与发布限制（M5.5 已复验）

- 受管安装器已同时配置 Codex 与 Claude Code Hook，并保护、升级和卸载两端定义；Codex MCP 另有独立配置入口，Claude Code 的五工具协议已通过真实客户端 E2E。
- 已在临时隔离目录安装并锁定 Claude Code 2.1.228；真实五工具 MCP 会话及读取分发物受管配置的自然 `UserPromptSubmit`/`Stop` 均已通过，本地模型替身确认经审批 L1 在请求前实际进入模型上下文。
- 当前实测发布矩阵是 macOS arm64 和 Linux arm64；x64、Windows 未验证。
- 首发版本固定为 `personalmemory-v0.1.1`，可按 Git tag 或版本化源码包安装，需要 Node.js/npm；暂不使用 Docker，桌面封装、签名安装包和自动更新尚未实现。
- 正式发布前仍需完成名称、域名、商标和发布渠道重名检查。

## 5. 有意留到 MVP 之后的产品能力

以下属于最终产品路线，不阻断当前 Chat Memory MVP，除非后续用户重新调整范围：

- Skill Memory：从成功任务和工具轨迹提炼可复用流程；
- Wiki Memory：导入和组织个人文档知识；
- CodeGraph：文件、符号、调用关系和影响范围；
- CodeBuddy 及更多 Agent 适配器；
- 按项目、来源和记忆类型装配 Agent 上下文；
- 增量同步、失败隔离和更完整的召回质量仪表盘；
- L2/L3 的复杂结构化编辑、审核和冲突治理；
- 多设备同步、可选远端部署、高级插件生态和家庭空间；
- 桌面应用、签名二进制、自动更新、Windows 和更多 CPU 架构；
- 跨设备/多用户前需要重新评估的应用级静态加密与密钥管理。

## 6. 明确非目标

- 多组织、多团队和复杂 RBAC；
- 企业计费、SLA 和大规模集群部署；
- 公共技能市场；
- 不可审阅、不可纠错、不可追溯的全自动记忆写入；
- 为加入自动 Hook 而重写上游记忆内核或在核心契约中加入客户端特例。

## 7. Token 与性能预算

- 普通 command Hook 本身不天然消耗模型 token；只有调用模型或向 Agent 上下文注入内容才增加 token。
- 自动本地捕获不得调用模型，因此不增加 Agent 对话 token；后台 L1–L3 提炼单独计量和展示。
- 自动召回会增加输入 token，必须设置相关性阈值和硬预算；初始目标约为每轮最多 1,000 token，后续以实测质量和成本调整。
- Hook 不得再次调用 Agent 形成隐藏对话轮次，也不得因失败触发无界重试。
- 产品应分别展示 Agent 对话、召回注入和后台提炼的开销，避免用户把统计 Hook、捕获 Hook与模型费用混淆。
