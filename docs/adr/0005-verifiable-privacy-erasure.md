# ADR 0005：可验证级联删除与备份策略

- 状态：accepted
- 日期：2026-08-11
- 适用范围：单用户、本地 SQLite、M3.4

## 背景

L1 记忆同时可能存在于来源 L0、SQLite/FTS/向量索引、可读 JSONL、L2/L3 派生文件，以及用户主动创建的导出和备份中。M2 的 tombstone 只保证产品不再浏览和召回，不能代表彻底删除。

MVP 的导出和备份均为明文资产，没有可独立销毁的每条记忆密钥。对这些文件做选择性原地重写容易破坏清单、校验和和恢复一致性；对未登记的用户复制品，产品也无法可靠发现。

## 决策

1. “彻底删除”只承诺 PersonalMemory 受控范围：当前活动数据根、可验证的来源引用、能精确匹配的 L2/L3 内容，以及由产品登记的导出和备份。
2. 活动数据立即删除或重写，不等待保留期到期：L0 来源按消息 ID 删除，L1 从 SQLite、FTS 和向量索引删除，可读 JSONL 原子重写，L2/L3 仅替换完整精确内容。
3. 产品创建可读导出或完整备份后，必须在本地账本登记其绝对路径和类型。执行级联删除时，对通过格式、路径和符号链接检查的登记副本整件删除，不进行选择性重写，也不宣称密钥销毁。
4. 用户自行复制、同步、改名或移动的文件不在可发现范围。执行前必须单独确认已自行处理这些副本；界面不得把该确认写成产品已验证。
5. 删除采用两阶段交互：先生成十分钟有效的服务端预览，再要求输入 `ERASE L1:<memory-id>`、确认删除登记副本并承认不可发现副本边界。待执行预览可以取消；执行开始后不可取消。
6. 执行先写不可恢复 tombstone，再逐层清理。所有步骤可幂等重试；部分失败返回 207、具体步骤和残留计数，不得返回伪造的成功。
7. 删除后重新查询 L0/L1、重读 L2/L3、扫描 JSONL 和登记路径，并确认 tombstone 存在。只有受控范围残留全部为零才标记 `complete`。
8. 删除凭据只保存记忆 ID、计划专用随机盐摘要、计划摘要、状态和计数，不保存正文、来源内容或用户理由。既有 HMAC 审计事件继续保留，因为它们不含正文或原始 ID，并用于证明高影响操作。

## 后果

- 受控范围内的删除结果可以重复验证，重建索引或同 ID 数据再次出现时仍由 tombstone 阻止复活。
- 一个登记备份只要可能含目标记忆就会整件删除；用户需要先决定是否另行保留，但保留后的未登记副本不再属于完成声明。
- 缺少来源引用、语义改写后的派生内容和外部复制品无法自动归因。MVP 必须明确报告这一边界，不能把“未发现”表述为“全设备不存在”。
- 后续若引入逐对象加密，可新增密钥销毁策略；在此之前不得以“加密删除”替代真实文件清理。
