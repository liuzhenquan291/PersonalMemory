# 黄金评测数据集

> 数据版本：`m2.1-v1`；Schema：`1.0.0`

M2.1 的黄金数据集位于
`packages/personal-memory/tests/fixtures/evaluation-v1.json`。它完全由合成内容组成，
采用 CC0-1.0，允许公开、重置和重复执行，不包含真实个人信息。

## 范围

数据集固定为 100 个带期望结果的样本：

| 类别 | 数量 | 主要失败模式 |
|---|---:|---|
| preference | 18 | 偏好不能被普通事实吞并 |
| fact | 18 | 事实值与来源必须一致 |
| decision | 16 | 已决定事项不能退化为建议 |
| conflict | 16 | 新值替代旧值且保留两条来源 |
| expired | 16 | 过期内容在评测时点不得回答 |
| no_answer | 16 | 无依据时不得猜测 |
| 合计 | 100 | — |

每个样本包含稳定 ID、类别、语言、评测时点、至少两轮且同时含 user/assistant 的会话消息、
查询以及独立的期望结果。
答案样本必须列出来源消息；无答案样本的答案为 `null` 且来源为空。

## 执行层级

- 每次提交：运行标记为 `smoke: true` 的 12 个样本，覆盖六类和中英文。
- M2 里程碑门：运行全部 100 个样本，并生成按类别统计的评测报告。
- M2.1 只固化数据契约和结构检查；检索质量执行器在 M2.3 接入，不能把结构测试当成召回能力通过。

现阶段统一 `npm test` 会验证数量、版本、类别分布、确定性 smoke 清单、来源引用、
过期时点、无答案约束，以及查询和 ID 不直接包含期望答案。修改现有样本必须提升
`evaluationVersion`；破坏字段兼容性时必须提升 `schemaVersion`。

## 验收场景映射

- E2E-01 使用独立的空 HOME 和网络拦截 fixture，不从黄金记忆数据派生。
- E2E-02 使用 preference、fact、decision、conflict 样本。
- E2E-03 使用 conflict、expired 样本，并在 M2.5 增加修改/失效动作。
- E2E-04 的多 schema 与故障注入 fixture 在 M2.6 增加。
- E2E-05 使用 conflict、expired 样本作为事实内容；索引、缓存、备份副本在 M3.4 增加。

黄金答案只存在于 `expected` 字段。评测执行器不得把 `expected` 传给召回或模型输入。
