# PersonalMemory MVP 威胁模型

> 基线日期：2026-08-07。范围是单用户、macOS/Linux、standalone、本地服务 + Web UI + MCP。service 多租户模式不在 MVP 支持范围。

## 1. 保护目标与攻击面

保护对象包括对话正文、L0-L3 记忆、来源关系、搜索索引、配置与密钥、备份、日志以及删除状态。主要入口是 loopback HTTP、Web/MCP 客户端、配置文件和环境变量、数据目录、导入/导出包、模型/embedding 端点与可观测性端点。

## 2. 威胁与控制

| ID | 威胁 | 当前证据/缺口 | MVP 必须控制 | 验证步骤 |
|---|---|---|---|---|
| T1 | 本地端口被同机恶意进程或浏览器调用 | 默认 loopback，但 API Key 可为空；v2 只要求非空 token | 产品层生成并保存高熵本地令牌；Web/MCP 不显示令牌；严格 Origin；非 loopback 拒绝启动 | M1.2、M1.3、M2.1 |
| T2 | 错误配置把服务暴露到局域网 | 当前只警告非 loopback + 无鉴权 | MVP 对非 loopback fail closed，不以警告代替阻断 | M1.2 |
| T3 | 模型或 embedding 在不知情时外发正文 | embedding 默认 none；但空 LLM Key 仍会创建 runner，触发提炼后可能尝试向默认 OpenAI 公网 URL 发送正文 | 默认零外联；未显式启用 provider 时不创建客户端；启用前展示 provider、目标地址、发送字段和用途 | M1.2、M2.2 |
| T4 | 代理环境变量绕过目标限制 | 当前依赖库/原生 fetch 行为未形成产品级 allowlist | provider 目标规范化并校验；网络隔离与恶意代理变量测试 | M1.2 |
| T5 | 遥测/日志泄露正文或密钥 | 遥测默认关闭；部分日志包含 session/instance/error，文件日志默认路径不适合产品 | 默认禁用遥测；正文与密钥禁止入日志；日志目录纳入私有数据目录和保留策略 | M1.2、M5.4 |
| T6 | 路径穿越、符号链接或宽泛删除覆盖用户文件 | LocalStorageBackend 防 `..`，但数据根和备份恢复尚无 symlink/ownership 门 | 数据根必须为受控绝对目录、0700；拒绝越界 symlink；删除前解析并展示精确目标 | M1.2、M2.6、M3.4、M5.3 |
| T7 | “删除成功”但 JSONL、派生层、备份仍留存 | 当前 L0/L1 删除只处理 SQLite/FTS/向量 | UI 区分失效、受控删除和彻底级联删除；返回删除清单与残留策略 | M2.5、M3.4 |
| T8 | 备份不完整、损坏或恢复覆盖有效数据 | M2.6 已为统一本地 SQLite 数据根提供显式 manifest、逐文件校验、原子切换和恢复前回退目录；跨安装编排与保留策略仍待发布阶段 | 保持 fail-closed 资产分类和损坏包先验校验；M5 增加升级/安装集成与回退目录生命周期 | M2.6、M5.3 |
| T9 | 备份/导出泄露正文或密钥 | M2.6 导出/备份以 0600/0700 创建并排除配置、环境密钥、日志、历史备份和导出物；用户复制到共享路径后的权限与保留仍不可控 | 操作前持续提示内容敏感；M5 增加目标路径权限引导、保留和安全销毁策略 | M2.6、M5.3、M5.4 |
| T10 | 密钥生命周期失控 | 当前可从环境变量或 YAML 读取，私有权限、轮换和撤销流程未建立 | 单一受控密钥入口；私有权限；日志/错误/导出/备份脱敏排除；支持轮换和撤销；不回显明文 | M1.2、M5.4 |
| T11 | 恶意导入造成资源耗尽或提示注入 | 当前 seed/API 有请求 schema，但产品导入边界未冻结 | 大小/数量/编码限制；内容作为数据而非指令；隔离解析与可取消任务 | M2.2 |
| T12 | 供应链或升级破坏数据兼容性 | 上游依赖多、schema migration runner 尚未建立 | 锁文件、审计、许可证、签名/校验、升级前备份和可回滚迁移 | M1.1、M5.2、M5.4 |

## 3. 强制安全不变量

1. 未完成配置引导也可以启动，但只进入本地只读/配置状态且没有任何外联。
2. 未明确启用 provider 时，模型、embedding、遥测、云存储、Redis 和代理均不得建立连接。
3. MVP 只允许 loopback 监听；健康检查不得泄露路径、密钥、正文或 provider 凭证。
4. 所有写入、恢复、卸载和彻底删除只能作用于经过校验的产品数据根；发现符号链接或所有权异常时停止。
5. 普通删除不得声称删除来源或备份；彻底删除必须有可验证的跨层清单。
6. 错误响应对用户可操作，对日志可诊断，但两者均不得包含密钥和完整记忆正文。
7. 配置、导出和备份必须分别定义密钥排除项；密钥轮换或撤销后旧凭证不得继续被后台任务使用。

## 4. 信任假设与非目标

- 假设操作系统账号和磁盘本身可信；MVP 不承诺抵御已取得该账号文件读取权限的攻击者。
- MVP 暂不提供磁盘静态加密；依赖系统磁盘加密和文件权限，应用级加密在保存多用户或跨设备同步前重新评估。
- MVP 不支持公网、多用户或共享主机部署；这些场景不能通过修改监听地址自行扩展为“受支持”。
