# 记忆浏览与来源状态

> API：`GET /api/v1/memories`

## 浏览契约

- `level`：单次选择 L0、L1、L2 或 L3，默认 L1。
- `query`：只搜索当前层级，最长 2,048 字符。
- `page`：从 1 开始，最大 10,000。
- `page_size`：1–50，默认 12。

L0/L1 无搜索词时使用上游查询接口的 limit/offset，在数据源执行分页；搜索时使用上游检索接口，
首版最多读取前 50 个命中并在响应中把 `total` 设为 `null`，避免把受限候选数伪装成完整总数。
L2 在只读索引中过滤、稳定排序后分页，只读取当前页文件；L3 最多一条。

浏览接口是只读 GET，仍要求 Bearer 或有效的 loopback 浏览器会话；浏览器会话读取不要求 CSRF，
因为请求不会改变状态。上游路径继续由编译期白名单约束，未开放写入、删除和实例销毁。

## 来源语义

- L0 标为“对话原文”：这是本地保存的原始消息，不是模型推断。
- L1/L2/L3 当前标为“来源未记录”：内容属于结构化记忆、情境摘要或核心画像，但当前存储没有
  可验证的下级引用，不能展示虚构的来源链。

现有 SQLite L1 写入会丢弃抽取结果中的 `source_message_ids`，L2/L3 文件也未保存下级引用。
因此本步骤只交付诚实的来源状态和详情入口；精确 L3→L2→L1→L0 下钻必须先完成来源字段持久化、
旧数据迁移和引用完整性检查，不能用相似检索结果代替。

## 界面状态

Web 管理端提供四层切换、当前层搜索、上一页/下一页、加载/空/错误状态和长文本详情对话框。
详情打开后焦点进入关闭按钮，Escape 可关闭；320px 窄屏保持搜索、层级、卡片和分页可用，
并遵循 reduced-motion 设置。
