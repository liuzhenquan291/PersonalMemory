# 记忆审核收件箱

## 目标与边界

M3.1 对新出现的 L1 结构化记忆采用默认待审核策略。审核状态保存在 PersonalMemory 自有 SQLite 表中，不修改上游记忆正文，也不把审核结果伪装成上游字段。L2/L3 审核留待后续来源链与冲突治理步骤。

状态只有 `pending`、`approved`、`rejected`。数据库中尚无记录的 L1 记忆按 `pending` 处理；只有 `approved` 能进入统一召回。普通记忆浏览仍可展示三种状态，收件箱使用服务端 `review_status=pending` 过滤。

## 操作语义

- 接受：只写审核状态。
- 修改后接受：先原子更新上游 L1 正文，成功后再写 `approved`；上游失败时保持原审核状态。
- 拒绝：必须填写原因，只写 `rejected`，不修改或删除上游正文。
- 批量请求：每项独立返回结果；同一记忆串行执行，乐观版本冲突不会影响批次中其他项目。
- 重复请求：相同目标状态、原因和前一版本视为幂等重试；不同结果使用旧版本时返回冲突。

审核表和内容状态表职责分离。审核决定是否允许召回，失效/删除 tombstone 决定是否允许浏览和召回；两层都必须通过才可注入上下文。

## 数据与可移植性

审核记录不保存记忆正文，仅保存层级、记忆 ID、状态、可选原因、版本和更新时间。完整备份包含产品 SQLite；可读 JSON/Markdown 导出显式包含审核记录，便于审阅和迁移。

## 已知限制

- 当前收件箱只处理第一页、每页最多 12 条；后续需要增加翻页或连续加载。
- 当前审核对象仅为 L1；L2/L3 在来源时间线和冲突治理完成前不开放审核。
- 拒绝不会执行彻底删除；完整级联删除属于 M3.4。
