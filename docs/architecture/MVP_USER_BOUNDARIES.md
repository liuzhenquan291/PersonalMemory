# MVP 来源、便携性与普通用户入口边界

> 状态：M4.7 生效

## 决定

### 1. L2/L3 来源

MVP 不修改上游 L2/L3 文件格式来补造派生引用。L0 是对话原文；带真实 `source_message_ids` 的新 L1 展示可核对的 L0 来源；旧 L1 以及当前 L2/L3 没有可验证引用时统一显示“来源未记录”。相似检索结果不能替代来源关系。

因此，MVP 对 L2/L3 的承诺是查看、内容层级标注和来源可用性披露，不是完整 L3→L2→L1→L0 下钻。完整派生链需要上游生成阶段持久化稳定引用，作为 MVP 后能力处理，不能通过离线猜测或大面积改写上游内核补齐。

### 2. 可读导出与重建

JSON/Markdown 可读导出继续是版本化、带校验结果、可人工阅读的用户资产，但它不包含检索索引、HMAC 密钥和全部运行时事实。MVP 不提供从可读导出导入、启动新安装或重建 SQLite/FTS/向量索引的入口，也不把它描述为恢复介质。

跨安装迁移与灾难恢复只承诺已验证的完整备份。ADR-0003 的“可读导出可重建”保留为长期方向；实现前还需冻结导入 schema、冲突与 tombstone 规则、审计引用迁移、索引重建和端到端验证。

### 3. Web 与 CLI

普通用户只有两个产品入口，不需要直接操作 SQLite 或拼接原始 Gateway API：

- Web：浏览和搜索 L0–L3、L1 审核、纠错/失效、冲突与替代治理、审计时间线，以及强确认彻底删除；
- 受管 CLI：一条命令安装，状态与 Agent Hook 信任检查，升级，可读导出，完整备份/校验/恢复，重启、停止和安全卸载。

首版源码分发仍要求用户在终端执行文档给出的单一命令；这不等于支持任意内部脚本或原始 API。Web 不读取或修改 Codex/Claude Code 配置文件，也不承诺所有系统管理操作都有按钮。安装器负责生成受管 Hook 定义，Codex 信任仍由用户在客户端核对，生命周期状态命令提供脱敏的 worker、backlog 与保留期状态。

## 验收口径

- 所有用户可见文案均区分“可验证来源”和“来源未记录”；
- README、路线图、ADR、数据说明和 Web 不再暗示可读导入或索引重建已经可用；
- Web 不再显示 MCP/Agent “即将可用”，并明确给出受管状态命令和数据迁移边界；
- M5.5 只按上述边界验证，不因后置能力未实现而误判失败，也不得反向扩大能力声明。
