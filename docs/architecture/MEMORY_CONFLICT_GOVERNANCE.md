# 记忆冲突与替代治理

## 决策边界

PersonalMemory 可以通过本地搜索展示相似候选，但相似不等于冲突。系统不得自动建立冲突、合并或替代关系；只有经过认证的用户明确提交后，关系才生效。

首版治理对象为 L1。L2/L3 的有效期元数据和关系表具备数据能力，但界面只开放 L1 冲突治理，等待后续来源链完善。

## 关系语义

- `conflicts_with`：两条记忆被用户确认为互相矛盾。关系对称存储，并暂停双方自动召回；两条记录仍完整可见，由用户继续合并或撤销判断。
- `supersedes`：主记忆替代旧记忆。旧记忆保留在上游和历史列表，但退出自动召回。
- 人工合并：用户选择一条现有记忆作为主记忆，可先修改主记忆正文，再建立 `supersedes`。循环校验必须在正文更新前完成。
- 撤销：关系转为 `revoked` 并保留创建、撤销时间和版本；撤销替代后，旧记忆在其他门禁通过时恢复召回。

同一层级的替代关系必须是有向无环图。自替代、直接循环和传递循环均拒绝；相同关系、原因和合并正文摘要可作为幂等重试，任一项不同则返回冲突。关系只保存合并正文的 SHA-256，不复制正文。

## 有效期与召回

每条记忆可设置 `valid_from` 和 `expires_at`。未到生效时间、已到过期时间或被活动替代关系指向的记忆不参与召回，但仍可浏览、导出和撤销治理状态。

召回需要同时通过内容状态、L1 审核状态和治理状态。活动冲突关系不替用户选择哪条为真，而是暂停双方召回；合并或撤销后再按剩余门禁恢复。

## 可移植性与限制

有效期及所有活动/已撤销关系保存在 PersonalMemory SQLite，并进入 JSON/Markdown 可读导出。关系只记录 ID、原因、状态、版本和时间，不复制记忆正文。

M3.2 不提供自动事实裁决、跨层自动合并或完整事件审计；通用操作审计在 M3.3 交付。
